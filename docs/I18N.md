# Languages (Godot client and web game)

English (source), 繁體中文 (`zh_TW`), 简体中文 (`zh_CN`), 日本語 (`ja`), Français (`fr`), Español (`es`).
Settings > Gameplay > Language: Auto (the device's language, English when we do not have it) or any of the six. The picker shows each
language in its own name. `--lang=ja` on the command line forces a language (tests and screenshots stay in English unless
they ask).

## How it works
- **English text is the message id.** Autoload `Lang` (`autoload/lang.gd`) loads `res://i18n/strings.json` into Godot's
  `TranslationServer`. A `Label`, `Button`, `CheckButton`, `OptionButton`, `LineEdit` placeholder or `tooltip_text` whose text
  is exactly a catalog key shows the translation by itself, and redoes it when the language changes. So a plain
  `label.text = "Settings"` needs **no code change**, only a catalog entry.
- **Text built at run time needs `tr()` on the whole sentence, then the format.** Godot only matches the exact string.
  ```gdscript
  label.text = "Step %d of %d" % [a, b]            # WRONG: "Step 2 of 5" is not a key
  label.text = tr("Step %d of %d") % [a, b]        # right: the template is the key
  label.text = "Signed in as " + name              # WRONG
  label.text = tr("Signed in as %s") % name        # right
  ```
  - In a `static func` or a class with no `tr` (RefCounted is fine, it is an Object) use
    `TranslationServer.translate("...")`; both give the same result. Prefer `tr(` in instance methods.
  - Placeholders keep the same **order** in every language (GDScript's `%` is positional). Reword the sentence if a language
    wants another order.
  - **No plural tricks** (`"bot" + ("" if n == 1 else "s")`): use two whole keys, `tr("%d bot") if n == 1 else tr("%d bots")`.
  - A name from data (weapon, class, map, mode, outfit...) that goes straight into a label is translated by the label. If the
    code changes it first (`.to_upper()`, `+ " x2"`, `"%s"` inside a sentence), translate it with `tr(name)` **before**
    that: `tr(w.name).to_upper()`, `tr("%s x2") % tr(w.name)`.
  - Things drawn with `draw_string`, `Label3D` or `RichTextLabel` do not translate themselves: call `tr()` on the text.
  - Player names, room codes, bot names ("Bot Wibble"), version numbers, key names (WASD, Esc) and the game's name are not
    translated.
  - Text from the server (error messages) is English: the client maps the ones it knows to `tr()` keys and shows the rest as is.
- **Fonts.** Fredoka has Latin letters only. For Chinese and Japanese `Lang` adds the device's own CJK fonts as the fallback of
  the UI font (a different list per language so the right Han glyph shapes are used), at a heavy weight. Never hard-code
  another font; use the theme font (`UiTheme.font()`), so the fallback applies.
- **Layout.** Texts are 20-60 % longer in French and Spanish and shorter in CJK. Labels wrap (`autowrap_mode`) or have room;
  do not size a control to the English text.

## The catalog
`godot/i18n/src/*.json` is the source (several files so people do not fight over one). Each key is the English text:

```json
{ "Step %d of %d": { "zh_TW": "第 %d 步，共 %d 步", "zh_CN": "第 %d 步，共 %d 步", "ja": "ステップ %d / %d", "fr": "Étape %d sur %d", "es": "Paso %d de %d" } }
```
Rules the checker enforces: all five languages present, same `%d %s %f` placeholders in the same order, same `{names}`, same
number of line breaks. A key that is in two files is taken from the file that sorts first (`00-common.json` has the shared words).

```
npm run i18n          merge src/*.json -> i18n/strings.json (the file the game loads; commit it)
npm run i18n:scan     lists tr() keys and .text = "..." literals that have no translation yet
node tools/i18n.js --file=NAME.json   check one source file
npm test              includes `node tools/i18n.js --check`
```

Japanese: です・ます, short. Chinese: concise, no filler; 繁體 uses Taiwan wording (滑鼠, 設定, 帳號), 简体 uses mainland
wording (鼠标, 设置, 账号).

## Web game (`public/index.html`)
Same six languages, same catalog format. `public/i18n.js` (classic script in `<head>`) + `public/i18n-data.js` (built by
`npm run i18n` from `godot/i18n/src` **and** `web-i18n/src`, so the two games share wording; commit it). Language picker:
Settings > More > Language (`localStorage` key `wobble_lang`; `?lang=ja` in the URL forces one; Auto = `navigator.languages`).
- A **DOM translator** rewrites any text node, `placeholder`, `title`, `aria-label` or `alt` whose whole trimmed text is a catalog key, now
  and for everything added later, and again when the language changes. So `el.textContent = 'Hello'` and static markup need no code, only
  a catalog entry (one key per text node: for `<b>Move</b> with WASD` the keys are `Move` and `with WASD`).
- Text **built in JS** uses `t('English')` or `tf('Got %s!', name)` (printf-style `%s %d %.1f %02d`, filled in order). Plurals are two
  keys. A data name inside a sentence: `tf('Got %s!', t(w.name))`.
- **Never read text back from the page to make a decision** (`btn.textContent === 'On'`): it is translated. Use state.
- Do not change the data tables (`MAPS`, `WEAPONS`, ...): `npm run content` exports them. Their names get catalog entries only.
- `npm run i18n:scan -- --web` lists `t()/tf()` keys without a translation. The page's `<html lang>` follows the language so the browser
  picks the right Han glyph shapes.
